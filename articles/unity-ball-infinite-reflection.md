Unityの学習を始めて最初に制作したブロック崩しで、ボールが水平または垂直方向にだけ反射し続ける問題が発生しました。

```text
← → ← → ← →
```

あるいは、

```text
↑ ↓ ↑ ↓ ↑ ↓
```

という動きを繰り返し、プレイヤーが待っていてもゲームが進みません。

この記事では、Unity初心者だった自分がこの問題をどのように調査し、修正したかを振り返ります。

## 問題は「たまにしか起きない」

通常はブロックや壁に当たるたびにボールの角度が変わります。しかし、衝突の仕方によっては速度が一方の軸へ極端に偏り、ほぼ真横または真上へ移動する状態になりました。

毎回起きるわけではないため、コードを眺めるだけでは原因をつかめませんでした。

そこで、まず`Debug.Log()`を使って衝突時の速度を確認しました。

```csharp
Debug.Log(rb.linearVelocity);
```

調べていくと、水平反射を繰り返すケースでは、X方向の速度が`8`または`-8`付近になっていました。

この時点で初めて、「反射処理そのものが止まっている」のではなく、「反射はしているが、角度がほぼ水平に固定されている」と切り分けられました。

## 速度が極端なときだけ補正する

ゲーム中のボール速度は`8`に固定していたため、壁へ衝突した際にX方向の速度がほぼ最大値になっているかを判定しました。

```csharp
if (Mathf.Abs(rb.linearVelocity.x) > 7.9f)
{
    // 真横に近い角度になっているため、進行方向を補正する
}
```

`Mathf.Abs()`を使うことで、右向きの`8`と左向きの`-8`を同じ条件で判定できます。

`7.9f`はどのゲームでも使える値ではなく、今回のボール速度が`8`だったために設定したしきい値です。ボール速度を変更する場合は、この判定も合わせて見直す必要があります。

垂直方向についても同様に、Y方向へ極端に偏った場合だけ角度を補正しました。

## 最初からランダムにしなかった理由

衝突するたびに進行方向を大きくランダム化すれば、無限反射は起きにくくなります。しかし、それではパドルの当て方によって方向を狙う操作感まで失われます。

そこで今回は、通常の反射は維持し、進行不能につながる角度になったときだけ補正する形にしました。

これにより、

- 普段の反射挙動は変えない
- パドルの左右どこに当てたかを反射角度へ反映する
- 水平・垂直の無限反射だけを防ぐ

という3点を両立できました。

## このバグから学んだこと

今回一番大きかった学びは、想像だけで原因を決めず、まず実際の値を見ることでした。

自分が行った流れは次のとおりです。

1. 現象を再現する
2. `Debug.Log()`で速度を確認する
3. どの値になったとき問題が起きるかを探す
4. 問題が起きる条件だけ補正する
5. 通常の操作感が壊れていないか再テストする

Unityを始めたばかりの頃は、エラーが出ていなければコードは正しいと思いがちでした。しかし、ゲームが意図どおりに進まないのも立派なバグです。

Consoleへ値を出し、「実際に何が起きているか」を確認することが、デバッグの第一歩だと実感しました。
