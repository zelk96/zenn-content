ChatGPTを使っていると、毎回こんな迷いがありました。

- 軽い相談なのに、上位モデル・最大の思考レベルで使う必要はある？
- 調査や実装のような重い依頼は、どこまで設定を上げるべき？
- そもそも、文章だけでは軽く見えても、直前までの会話では複雑な作業の続きかもしれない。

自分は最初、常に高性能モデルと最大の思考レベルを選んでいました。
安心感はある一方で、週間上限が早く減ってしまい、「この依頼ならもう少し軽い設定で十分だったかも」と後から思うことが多かったです。

そこで作ったのが **ModeGuide for AI** です。
ChatGPTへ送る前の文章から、今回の依頼に合いそうなモデルと思考レベルの目安を表示し、必要ならワンクリックで設定変更まで行うChrome拡張です。

この記事では、何を解決したかったのか、どういう設計にしたのか、実装で詰まった点、
Chrome Web Storeへの申請までをまとめます。

## 作りたかったのは「最強設定を禁止する」ツールではない

前提として
ModeGuideは「常に低い設定にすれば節約できる」と言いたいわけではありません。

調査、複数条件の比較、長い実装、重要な判断では、高い推論力を使う価値があります。
逆に、感想への返信、短い確認、文章の軽い整形にまで重い設定を使い続けると、待ち時間や利用上限を必要以上に使う可能性があります。

目標は、**今回の作業に対して過不足が少ない設定を選びやすくすること**です。

そのため、結果は「最適」や「必ず節約できる」とは表現していません。
あくまで、入力内容から推定した目安です。

## ModeGuideの主な機能

### モデルと思考レベルを同時に提案する

モデルだけを選んでも、思考レベルが必要以上に高いままだと、期待したほど軽くならないことがあります。

ModeGuideでは、次の組み合わせで提案を出します。

- GPT-5.6 Sol / Terra / Luna / 5.5
- 軽 / 中程度 / 高い / 非常に高い / 最大

例えば、短い感想共有ならLuna＋軽、方針相談ならTerra＋中程度〜高い、調査と実装が同時に絡む作業ならSol＋非常に高い、といった形です。

### 優先方針と残量を反映する

利用者が「品質」「バランス」「節約」のどれを優先するか、週間上限がどの程度残っているかも設定できます。

同じ依頼でも、品質を優先するなら少し上の設定を、残量が少ないなら安全な範囲で一段軽い設定を提案します。

### 添付資料の有無を考慮する。ただし中身は読まない

ChatGPTでは、文章だけでなく画像やファイルを添付するケースがあります。

資料を参照するだけなら、本文だけの場合より少し慎重に判断します。
一方で、資料や画像を詳細に精査する依頼は、より高い設定が必要になりやすいので、添付の扱いを分けました。

重要なのは、ModeGuideが添付ファイルの中身を読まないことです。
画面上に添付があるかだけを検出し、ユーザーが選んだ「参照用」か「全体・画像を精査」の扱いを判定に使います。

### 短い「続き」指示は、先に文脈の利用を確認する

「了解、改修をお願い」のような一文は、その文だけなら軽い会話に見えます。

でも、直前まで複雑な設計や実装の話をしていたなら、実際には重い作業の開始かもしれません。

ここは自動で会話全体を読むのではなく、曖昧な継続指示を検出したときだけ、次のどちらかを明示的に選べるようにしました。

- この文章だけで判定する
- 直近の会話を使う

後者を選んだ場合だけ、画面に表示されている直近文脈を一時的に使います。
保存や外部送信はしません。

## 推奨設定への切り替えは、1クリック＋画面確認にした

最初は「推奨設定を開く」だけの機能でした。

ただ、それでは利用者がメニューを開いて、モデルを選んで、さらに思考レベルを選ぶ必要があります。提案が合っていても操作が面倒なら、結局使われません。

そこで、結果カードの「推奨設定に切り替える」を押すと、以下を順番に行うようにしました。

1. ChatGPTの設定メニューを開く
2. 推奨モデルを選ぶ
3. 推奨思考レベルを選ぶ
4. 入力欄の表示が推奨値と一致したことを確認する

この「最後に見えている値を確認する」がかなり大事でした。

ChatGPTのメニューUIは状況によって表示が変わります。
たとえばモデル選択時に思考レベルが自動変更されたり、メニューの要素が再利用されたりします。
クリックイベントが発火しただけでは、本当に切り替わったとは言えません。

そのため、操作自体が途中で検出できなかった場合でも、入力欄の最終表示が推奨値と一致していれば成功扱いにしています。
逆に確認できなければ、失敗を装って誤解を生まないよう、手動設定を案内します。

## 実装ではルールベースを選んだ

初版の判定ロジックは、外部APIを呼ぶAI判定ではなく、ブラウザ内で動くルールベースです。

主に次のシグナルを組み合わせています。

- 相談・実行・雑談のどれに近いか
- 調査、比較、設計、実装、複数工程などのキーワード
- 添付資料の扱い
- 現在性のある情報を調べる必要があるか
- 判断ミスの影響が大きいか
- 文章量、優先方針、週間残量

重い依頼に寄せすぎると「いつもSol」になり、節約を優先しすぎると本当に必要な場面で弱い設定を出してしまいます。

そのため、実際の会話をもとにテストケースを増やしながら調整しました。たとえば次のようなケースです。

- 「市場横断調査・第一実験選定について相談したい」→ Terra＋高い
- 「市場横断調査・第一実験選定フェーズを開始して」→ Sol＋非常に高い
- 写真を添付して「似合う髪型を教えてほしい」→ 添付を考慮した相談設定
- 「ありがとう、これでいこう」→ Luna＋軽

初版では、万能な正解を出すことよりも、理由と一段上げる目安を表示して、利用者が自分で最終判断できることを重視しました。

## プライバシー設計

ChatGPTの入力欄を扱う拡張だからこそ、最初からデータの扱いを狭くしました。

- 対象サイトは `https://chatgpt.com/*` のみ
- 権限はユーザー設定を保存するための `storage` のみ
- 未送信文章を読むのは「判定する」を押したときだけ
- 直近文脈は、利用者が明示的に選んだときだけ一時利用
- 未送信文章、文脈、添付内容、判定結果を保存しない
- 外部サーバー、解析SDK、広告SDK、リモートコードを使わない

Chrome Web Storeの申告でも、扱うデータを「ウェブサイトのコンテンツ」に限定し、単一用途・権限理由・プライバシーポリシーの記載を実装と一致させました。

## おわりに

モデル選択が増えるほど、AIを使う前の小さな判断コストも増えていきます。

ModeGuideは、その判断を完全に自動化するものではありません。
送信前に一度だけ「この設定で本当に重すぎないか、軽すぎないか」を考えるきっかけを作るための拡張です。
